# 2026-10-12 홈 개발 회수와 축구 장면 검증

## 확인한 작업

- 최신 홈 작업은 `codex/football-realism-20261012`, PR #25의 `a2a4c18`입니다. 이전 로컬 `5d94e77`보다 61개 커밋이 앞섰습니다. 기존 작업을 덮어쓰지 않고 같은 브랜치를 이어 사용합니다.
- 기존 소스 CI는 성공했고 APK/AAB/lint도 성공했습니다. Android API 34/35 검사는 호스트 에뮬레이터 RenderThread의 SIGSEGV와 연결 해제로 완료되지 않았습니다. 빌드 성공을 관전 성공으로 해석하지 않습니다.
- CI `36e75f8`은 공식 지원 `-gpu swangle`로 ANGLE/SwiftShader를 명시했습니다. 두 API 모두 호스트 연결 해제 없이 8개 검사를 수행했습니다. 관전/오프라인 저장/재접속 등 6개는 통과했고 아래 두 검사 코드 오류가 드러났습니다.
- 선수단 재진입 검사는 DOM 요소 객체를 반환하고 문자열 `true`만 기다렸습니다. 불리언으로 바꿨습니다. 삶 돌아보기 검사는 전체 재렌더링 전의 select/body를 읽고 있었습니다. 각 페이지의 현재 DOM을 다시 찾고 실제 세 경기의 득점·목표·미달 판정·점수를 비교합니다. 모든 검사와 API 두 버전을 유지합니다.
- 후속619c223은 소스 CI와 API35 네이티브8/8을 통과했습니다. API34는 취임 대화의 두 번째 답변 좌표가 사라지고 로딩 검사도 실패했습니다. JS 초기화와 네이티브 로드 완료를 구분하고, 실제 대화 페이지/답변 단계 변화 및 네이티브 로딩 측정 완료를 기다리도록 검사를 보강합니다. 임의의 긴 sleep이나 표시 경계 완화로 통과시키지 않습니다. 이 후속 검사의 최종 결과는 PR25의 체크를 확인합니다.

## 이번 변경

- 침투 패스 순간의 공, 실제 두 번째로 뒤에 있는 수비수, 중앙선을 사용하는 `offsideLine`을 공유합니다. 선수는 합법적인 패스에서는 선 안에서 기다렸다가 공이 떠난 뒤 전진합니다. 양 팀과 12개 포메이션 모두 같은 원칙입니다.
- 패스 전에 수비가 연속적으로 준비 위치로 이동하고, 패스가 떠나는 순간의 선을 고정합니다. 수비 추격 때문에 판정선이 나중에 바뀌지 않습니다. 침투/오프사이드 연출에 선을 표시합니다.
- 오프사이드 수신자의 순간 이동을 없앴습니다. 먼저 패스가 연결되고 휘슬, 위반 지점의 간접 프리킥, 수비의 접근과 다음 패스로 이어집니다. 슈팅/선방/골 장면은 생성하지 않습니다. 모든 연출 경계에서 공과 선수 위치가 연속적입니다.
- 상대의 침투/연계/중거리 장면도 중앙 미드필더가 시작합니다. 측면 선수가 공 없이 중앙 패스의 출발자로 쓰이던 문제를 줄입니다.
- 실제 `long_shot`의 득점 확률과 추정 xG를 가까운 연계 슈팅보다 낮게 계산합니다. 기존 연계 슈팅의 확률을 쓰던 문제를 수정했습니다. 실제 축구 데이터에 맞춘 검증된 xG 모델이라는 의미는 아닙니다.
- 기존에 확정된 점수/추정 xG/이벤트/구단 영수증은 다시 계산하지 않습니다. 미래 경기 결과는 확률 변경의 영향을 받습니다. 통과하던 승부차기/유럽 결승 테스트는 실제 균형 전술로 해당 경기에 진출하는 사례를 사용하며 승부차기 결과와 결승 정산 검사를 유지합니다.
- 전체 검사기는 첫 실패에서 멈추지 않고 모든 실패 파일을 보고한 뒤 실패 종료합니다. 필요한 검사를 숨기지 않습니다.

- QA 파일/사진/개인 저장과 진단 ZIP은 ignored `work/`에만 보관합니다. schema 10, 저장 키, 패키지 ID와 초상화 예산은 유지합니다.

## 실제 축구와 다른 구조적 이유

현재 엔진은 1분마다 찬스/공격 유형/성공을 뽑고, Movement가 공과 선수의 움직임을 만들어 보여 줍니다. 이번 변경은 침투 패스의 위치와 확률 불일치를 줄이지만 22명이 같은 공을 보며 판단하는 물리 시뮬레이션으로 바뀐 것은 아닙니다. 특히 엔진의 오프사이드 사건은 아직 미리 정한 침투 타이밍 표본에서 결정합니다. 화면의 패스 순간과 판정을 일치시킨 것이며 실제 위치 상태로 모든 사건을 생성한다는 의미는 아닙니다.

다음 구조 개선은 공 위치/속도/소유자와 22명 위치/속도를 하나의 공간 상태로 유지하고, 패스 선택·경로 차단·수신·수비 경합이 그 상태에서 일어나도록 하는 것입니다. 고정 간격 계산과 보간 표시를 분리하고, 경기 RNG·저장 복원·확정 기록을 먼저 검증해야 합니다. 한 번에 외부 엔진을 갈아 끼우거나 이미 끝난 기록을 재시뮬레이션하지 않습니다.
