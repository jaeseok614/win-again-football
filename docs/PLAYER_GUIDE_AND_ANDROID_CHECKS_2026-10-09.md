# 새 선수·전술·기록 기능 안내와 Android 검증

처음 안내의 기존 여섯 단계와 건너뛰기, 설정에서 다시 보기 흐름을 유지했습니다.
선수 단계에는 주발·세부 포지션·성격·6축 코치 리포트와 역할별 강조 능력을,
전술 단계에는 12개 포메이션과 위치·능력·체력별 코치 선발 비교를 설명합니다.
킥오프 단계에는 경기 기록의 실제 장면 다시 보기·공격 경로 분석과 상대 선수 비교를
짧게 안내합니다. 이 문구는 경기 능력·결정·수치를 바꾸지 않습니다.

README에도 실제 메뉴에서 찾는 방법과 이름 검색 없는 32명 영입 후보를 설명했습니다.
다른 컴퓨터에서 개발할 때는 원격 main과 source/를 사용합니다. 과거 v22 ZIP에서
현재 코드나 폐기한 선수단을 복원하던 README의 설명을 제거했습니다.

- 진행 중인 유효 구단의 5R 준비에서 설정 → 처음 안내 다시 보기 → 전체 18명
  선수단 → 전술 → 건너뛰기를 실제 조작했습니다. 구단 전체 상태와 RNG·자금·
  일정은 같고, 홈으로 돌아온 뒤 전체 이동용 저장 payload도 같습니다.

  두 버튼은 46px입니다. 길어진 안내는 기존 창 내부 스크롤을 사용합니다.

실패한 저장/복원 시험은 앞선 리플레이 시험이 저장한 경기 종료 상태를 이어받았습니다.
이 상태에서 주 버튼은 킥오프 대신 결과 확정을 실행하므로 “진행 경기 정지” 조건을
충족하지 못했습니다. 이 시험에만 실제 엔진의 새 준비 구단을 설치하고 기존 저장/
가져오기 경로를 그대로 시험합니다. 정지 검증에는 F.running 조건도 더했습니다.
제품의 저장·복원·킥오프·정지 구현을 변경하지 않았습니다. 후속 원격 실행의 실제

## 최종 실제 플레이·다른 기기 이동 확인

수정 커밋 `dbb56c8d269b9ab4a3f610e95339650cb1e5e614`의
[소스](https://github.com/jaeseok614/win-again-football/actions/runs/37875003286),
[공개 배포](https://github.com/jaeseok614/win-again-football/actions/runs/37875002373),
[Android 빌드·lint·에뮬레이터](https://github.com/jaeseok614/win-again-football/actions/runs/37875003313)가
모두 성공했습니다. 내려받은 계측 XML은 6 tests / 0 failures / 0 errors / 0 skipped입니다.
그 실행의 APK 안 assets/game/index.html SHA256도 위 생성 게임 값과 같습니다.
물리 휴대폰에 설치한 시험은 아닙니다.

실제 5R에서 부상 1명·정지 1명을 제외한 코치의 체력 우선 4-3-3을 비교/확정했습니다.
평균 적합도 82→88, 체력 92→95이며 비교 전후 구단은 같고 적용/격려 전체 상태는
독립 모델과 같습니다. 격려 선택 전에는 결과가 없고 선택 뒤 긍정 8명/변화 없음 3명이
표시됐습니다. 하프타임 두 명 교체는 기회 0회, 65분 골키퍼/공격수 두 명 교체는
기회 1회입니다. 최종 2:1, 슈팅 7:3, 기회 9:4, 실제 공격 13장면입니다.

모든 실제 중간 상태와 종료·결산은 독립 엔진과 같습니다. 65분 전 장면은 원래
비카리오우, 이후 장면은 포스털로 재구성됩니다. 72분 교체 선수 히샬리쏭의 결승골과
전체 장면 탐색도 확인했고 리플레이 전후 전체 구단이 같습니다. 결산 뒤 6R 준비,
7위/10점/£187,750이며 실제 3승 과제 보상 £20,000이 한 번 반영됐습니다.

이 90분 저장 파일을 별도 origin의 새 환경에서 실제 파일 선택→미리보기→불러오기
흐름으로 옮겼습니다. 전체 이동 payload가 같고 재접속 뒤에도 같으며 자동으로 다음
경기에 넘어가지 않습니다. 두 환경에서 각각 명시적으로 확정한 전체 결산이 같습니다.
기기 간 자동 동기화가 아니라 저장 파일로 이동하는 기능입니다.
