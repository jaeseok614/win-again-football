# 구단 그림과 연속적인 경기 움직임 — 2026-10-08

이번 개발은 기존 경기 결과를 바꾸지 않고 관전과 감독 생활의 표현을 개선한다.
FM Mobile의 전술/감독 업무 화면과 FC Mobile의 공격·수비 움직임 공식 사례를
참고했다. 원본 그림, 생성 방식과 최종 프롬프트는
[구단 이미지 기록](CLUB_VISUALS_2026-10-08.md)에 있다.

## 경기 표현

- 공 회수→확보→첫 패스→운반→크로스/침투→슈팅→골키퍼 대응의 기존 시간축을 유지한다.
  운반 중 공이 발 앞에 나갔다 돌아오는 터치와 곡선 돌파를 추가했다.
- 윙의 돌파와 박스 안 공격수의 움직임을 구분한다. 동료는 먼 포스트로 침투하거나
  뒤에서 지원하고, 측면 수비수는 돌파 선수를 따라간 뒤 박스로 복귀한다.
  별도 중앙 수비수는 슈팅할 선수를 따라간다.
- 압박은 폭과 수비선을 높이고 내려앉는 수비는 좁고 낮게 그린다. 실제 기록에 있는
  상대의 추격/리드 보호 지시도 표현에 반영한다. 전술 변경 뒤 직접 재개하면
  약 650ms 동안 새 위치로 이동한다. 멈춘 화면에서는 위치 재정비가 진행되지 않는다.
- 진행 중인 장면은 시작 당시의 선수 신원을 보존한다. 교체 창에서 선수를 바꾸어도
  공을 운반하던 선수가 갑자기 바뀌지 않는다. 장면 종료 뒤 현재 선수단으로 돌아온다.
- 기록된 득점의 공 도착 뒤에만 짧은 세리머니를 보여준다. 얼굴 대신 작은 유니폼,
  번호, 머리와 발로 표현하고 실제 초상화 셀에서 읽은 피부색을 동일 신원에 사용한다.
- 공은 선수보다 앞의 레이어에 남는다. 골키퍼 전진·준비·다이빙·공 도착, 헤더의
  공 높이와 점프, 돌파 차단의 태클 표현을 유지한다. 멈춤/동작 줄이기를 지킨다.

이는 기록된 사건의 2D 표현이다. 새 충돌 물리, 별도 태클/패스 통계, 추가 체력 소모나
득점 보너스를 만들지 않는다. schema/engine 10, 현재 유효 저장·계약·선수 신원,
난수와 38/46경기 일정은 그대로 사용한다.

## 구단 이미지와 작은 화면

- 기본 얼굴 28셀을 유지하고 확장 얼굴을 16개에서 64개로 교체했다. 상대 한 팀의
  11명은 서로 다른 얼굴을 사용하며 영입/유소년도 안정적인 신원 해시로 배정한다.
- 경기장 도착·라커룸·기자회견·훈련·유소년·우승의 6개 그림을 공유 아틀라스로
  제공하고, 트로피 없는 승격 그림을 별도로 추가했다. 홈의 기본 모바일 요약에도
  그림이 보인다. 실제 우승/승격 확정 여부에 따라 홈과 시즌 결산 그림을 고른다.
- 2~5부의 확정 2위에는 승격 그림, 확정 1위에는 우승 그림을 표시한다.
  아직 진행 중인 시즌의 현재 순위, 1부 2위에는 승격을 미리 표시하지 않는다.
- 경기장은 4~5부의 낡은 잔디/작은 관중에서 상위 리그의 깔끔한 잔디/더 많은 관중으로
  바뀐다. 실제 관중 수, 구장 시설 능력치 또는 기상 효과로 주장하지 않는다.
- 작은 대화 창의 네 가지 핵심 선택은 세로/짧은 가로에서도 스크롤 없이 보인다.
  그림은 작은 썸네일이며 자세한 반응과 규칙만 내부에서 스크롤한다.
  경기 점수·공·중계·핵심 통계와 조작은 한 뷰포트에 남는다.

## 성능과 측정

경기장 배경은 크기/DPR/리그가 바뀔 때만 그리는 별도 캔버스에 캐시한다.
ResizeObserver로 경기장 크기를 보관하고 오래된 WebView에서는 측정으로 대체한다.
발 스타일은 약 80ms 간격으로 캐시한 발 요소에만 적용한다. 선수 카드 전체에
상속시키지 않으며 변하지 않은 골키퍼 각도도 다시 쓰지 않는다. 일시 정지하면 발
자세가 유지된다. 숨긴 화면에서는 기존 원칙대로 경기 애니메이션을 돌리지 않는다.

최종 공개 단일 파일은 **2,607,362바이트**, Android 오프라인 자산은
**2,608,991바이트**다. Android SHA256:
`815c2a09003c28f0b2711d778a75e403cbdb9f62a233bf29a2a6d1b406400905`.
64개 확장 얼굴 WebP는 208,648바이트로 이전 활성 16개 JPEG 236,488바이트보다 작다.
전체 번들은 새 구단 그림을 포함해 직전 2,152,178바이트보다 약 21% 늘었다.

실제 Chrome 360×640, CPU 4배 제한, 파일 URL, 각 3회 새 브라우저 컨텍스트 로딩과
10초 실제 경기의 측정이다. 최종 비교는 새 파일을 먼저 실행했다.

| 측정 | 직전 파일 | 최종 파일 |
|---|---:|---:|
| 로딩 중앙값 | 973.7ms | 927.7ms |
| 기본/확장 얼굴·6장면 아틀라스 decode 중앙값 | 46.9ms | 59.2ms |
| 10초 rAF 표본 수 | 504 | 507 |
| 프레임 간격 중앙값 / 95백분위 | 16.7 / 33.4ms | 16.7 / 33.4ms |
| 50ms 이상 작업 수 / 최대 | 18 / 126ms | 7 / 153ms |

이는 한 PC의 작은 표본이다. 초기 실행 순서와 시스템 부하에 따라 로딩과 프레임이
달랐다. 수정 전 비교에서는 새 파일의 프레임 95백분위가 더 나빠져 스타일 갱신 범위를
좁혔다. 위 수치는 수정 뒤 최종 비교이며, 항상 빠르거나 물리 Android에서도 동일한
성능을 보장한다는 뜻은 아니다. 새 별도 승격 그림의 decode는 이 표에 포함하지 않고
브라우저/Android 계측에서 별도로 검사한다.

## 검증

- 전체 **103 suites / 789 checks**, 공개 PWA 14개, Android 자산/브리지 11개.
- 실제 Chrome 8개 크기: 320×568, 360×640, 390×844, 412×732, 640×360,
  844×390, 768×1024, 1440×900. 일곱 경기 단계의 한 화면, 중계 14/15px,
  최소 44px 조작, 돌파/크로스/선방/헤더/태클 장면을 검사한다.
- 대화의 네 결정은 여섯 세로/가로 크기에서 모두 보인다. 전체 선수단 18명과
  검색어 없는 필터·검색 지우기·초기화도 실제 브라우저로 확인했다.
- 실제 90분 경기의 전체 상태가 별도 엔진 실행과 정확히 일치하고 새로고침으로
  저장을 정확히 복원한다. 득점 도중 계획 창을 열어 정지/직접 재개도 검사한다.
- 실제 46경기를 완료한 5부 2위 검증 구단으로 승격 그림을 확인했다.
  결산 열람만으로 해/리그/시즌이 넘어가지 않으며 원본 상태를 바꾸지 않는다.
- Android 계측에 기본 홈 그림 표시, 세 이미지의 실제 WebP decode,
  상대 11명의 서로 다른 얼굴 검사를 추가했다. APK/AAB/lint/에뮬레이터의 최종 결과는
  이번 원격 커밋의 CI를 확인해야 한다. 로컬 자산 검증만으로 APK 검증을 주장하지 않는다.

개인/합성 저장, 측정 도구와 QA 이미지는 커밋하지 않는다. Google Play 공개 게시나
서명한 AAB 제출은 이번 개발에 포함하지 않았다.
