# 경기 준비와 이전 삶을 기억하는 이야기

## 참고 범위

- [FM26 Mobile 공식 소개](https://www.footballmanager.com/fm26/features/football-manager-26-mobile-new-features-showcase): 상대별 경기 준비, 코치 피드백, 선수·언론 관계를 참고했습니다. 기능을 그대로 재현했다는 뜻은 아닙니다.
- [WEBTOON Back to First Base 공식 소개](https://us.webtoons.com/en/sports/back-to-first-base/list?title_no=10883): 끝난 스포츠 경력의 후회와 다시 주어진 기회라는 소재를 참고했습니다.
- [WEBTOON Reborn Rich 공식 소개](https://us.webtoons.com/en/drama/reborn-rich/list?title_no=4956): 다른 자리에서 다시 선택하는 삶과 권력 관계라는 소재를 참고했습니다.

웹툰은 공식 작품 소개만 읽었습니다. 회차 대사·인물·그림·사건을 가져오지 않았습니다. 토투넘, 코치, 구단주와 감독의 대화는 이 게임을 위한 새 가상 이야기입니다.

## 경기 전 코치의 작전

필수 양 팀 선발 확인은 유지합니다. 같은 브리핑의 ‘코치의 작전’에서는 현재 실제 선발·배치·역할을 읽어 체력 부족, 일시 집중 부담, 낯선 역할, 연결 부족, 상대에 맞춘 전술 관찰 중 우선 과제 하나를 보여줍니다. 최근 세 확정 리그 결과와 현재 최후통첩/약속도 함께 읽습니다.

전술 검토는 기존 창을 열 뿐입니다. 추천 읽기, 창 닫기, 선수 확인은 선발·능력·RNG·시간을 바꾸거나 킥오프하지 않습니다. 양 팀 22명의 실제 이름과 기존 핵심 선수 보고서를 그대로 확인할 수 있습니다.

## 구단주마다 다른 세 경기 약속

새 첫 삶과 환생부터 선택적 `rebirth.contractStyle`을 캠페인 seed의 기존 구단주 성격에 묶습니다. 필드를 갖지 않은 현재 v10 구단은 진행 중 약속까지 `classic` 규칙을 유지합니다. 이미 진행한 구단의 도전 편입도 기존 규칙입니다. 저장 schema, storage key, 경기 엔진은 그대로입니다.

| 새 구단주 | 신중한 목표 | 도전 목표 |
| --- | --- | --- |
| 승부 우선형 | 1승 이상 | 2승 이상 |
| 선수 보호형 | 총 4실점 이하 | 총 1실점 이하 |
| 언론 주도형 | 3득점 이상 | 6득점 이상 |
| 재정 현실형 | 승점 3점 이상 | 승점 5점 이상 |

구단주 차례에만 바뀝니다. 팬/코치 차례와 6경기 주기, 실제 다음 리그 3경기 판정, 기존 보상 6/14·미달 압박 14/24는 유지합니다. 선택 전에 약속 조건은 알려주되 아직 뛰지 않은 경기의 결과를 예고하지 않습니다.

약속의 마지막 리그 경기가 확정되면 ‘지킨 말’ 또는 ‘남은 말’ 면담이 도착합니다. 정확히 선택한 목표, 세 실제 스코어, 집계값을 보여줍니다. 컵, 부분 기록, 미확정 결과로 면담을 만들지 않습니다. 구단주/팬/코치마다 시즌에 한 번씩만 후속 면담을 제공합니다. 일반 사건에 묻히지 않게 완료 약속과 최후통첩 대화를 먼저 표시합니다. 필수 취임은 언제나 먼저입니다.

## 이전 삶을 기억하는 감독

두 번째 삶부터 실제 직전 회차의 경질/귀환, 경기 수, 승리 수와 선택한 기억을 첫 독백에 사용합니다. 감독만 지난 삶을 기억하며 NPC에게는 첫 만남입니다. 현재 인물에게 아직 겪지 않은 패배·논란을 덮어씌우지 않습니다.

- 첫 완전 리그 확정: ‘같은 비, 다른 대답’.
- 그 대화의 마지막 답변 후 두 실제 리그 경기: 정확한 답변과 실제 승점을 기억하는 후속 대화.
- 실제 최후통첩: ‘이번에는 문을 닫기 전에’.
- 실제 세 경기 유예 성공: ‘끝나지 않은 아침’.

첫 질문의 세 선택과 마지막 두 선택을 직접 고릅니다. 답변 반응과 효과는 선택 뒤에만 공개합니다. 기존 대화 영수증과 관계별 최신 효과, 총 집중도 ±2%, 두 확정 리그 경기 만료, 킥오프 뒤 효과 고정을 사용합니다. 영구 능력·재정·건강·이미 확정된 압박을 다시 계산하지 않습니다.

## 한 화면의 경기 기록

‘핵심 기록’, ‘팀 비교’, ‘선수 평점’, ‘주요 장면’으로 기본 경기 기록을 나눴습니다. 전체 이름은 유지하고 선수 카드에서 실제 상세 보고서를 엽니다. 폭 360px 이하에서는 선수 두 명/장면 한 개씩, 다른 화면에서는 세 명/두 장면씩 넘깁니다. 가로 화면은 같은 항목을 옆으로 배치합니다. 44px 조작, 기존 리플레이와 명시적 결과 확정을 유지합니다.

아직 공이 도착하지 않은 표시 중에는 해당 결과·xG·결과 확정을 숨깁니다. 전체 경기 후 회복·경험·재정의 긴 보고서는 명시적으로 ‘결과 상세’를 선택할 때만 펼칩니다. 이 상세 페이지와 ‘전체 능력’ 선수 목록의 내부 세로 스크롤은 의도적으로 유지합니다.

## 검증 기록

‘삶 돌아보기’에서는 현재/이전 삶의 확정 리그 성적표, 실제 판정이 끝난 약속과 그 세 스코어, 리그 결과를 세 경기씩 볼 수 있습니다. 읽기와 페이지 이동은 환생·유예·저장 수정을 하지 않습니다. 이전 삶의 계약 성향도 당시 규칙으로 해석합니다. 추가 저장 필드 없이 기존 회귀 기록을 읽습니다.

미완료 대화를 먼저 이어 주고, 그다음 최후통첩·완료 약속·기억 대화를 일반 사건보다 먼저 알립니다. 모델의 사건 시간 순서는 유지하며 화면 목록만 우선순위를 적용합니다. 필수 취임 진행은 별도의 기존 안내가 담당합니다.

- 초기 전체 검사: 150 suites / 1119 checks 통과. 이후 좁은 화면/대화 우선순위 검사를 보강했습니다. 최종 수치는 HANDOFF 최신 항목을 보세요.
- 실제 브라우저에서 두 번째 삶의 취임과 4배속 전체 경기(전반 45+3, 최종 90+5, 실제 98분, 3:0), 하프타임 명시적 재개, 선수 상세 복귀와 명시적 결과 확정을 확인했습니다.
- 320×568 / 390×844 / 844×390 / 1280×800에서 실제 경기 기록 104개 페이지: 본문 넘침 1px 이하, 모든 버튼 44px 이상. 경기 전 코치 브리핑도 네 크기에서 내부 스크롤 없이 확인했습니다.
- 128개 실제 seed × 두 선택을 각각 9경기 진행한 진단에서 성격/선택별 32회 중 달성: 승부 32/25, 보호 32/28, 언론 26/9, 재정 32/29. 기본 선발·균형 전술·훈련/교체 없이 낸 첫 구단주 약속의 표본이며 전 시즌 난이도나 모든 전략의 성공률을 뜻하지 않습니다.
- QA 저장, 진단 JSON, 사진과 검사 로그는 저장소 밖 `work/qa-fm-rebirth-20261011`에 보관합니다. 실제 사용자의 공개 사이트 저장을 사용하지 않았습니다.
- 안드로이드 검사는 첫 장면의 계약서→두 번째 장면의 토투넘 설명, 보고서 닫기→같은 가이드 단계, 명시적 다음 진행을 검사하도록 수정했습니다. 새 기록의 모든 페이지 검사도 추가했습니다. 오프라인 자산 검증과 네이티브 에뮬레이터 검증은 별도로 기록합니다.
- 추가 전체 검사 **152 suites /1130 checks** 통과. 실제 회귀 기록20페이지와 약속 미달 면담24페이지를 같은 네 크기에서 넘침 없이 확인했습니다. 약속 미달의 정확한 목표6골/실제0골/세 결과, 두 답변 뒤 실제 집중 반응11명 상승/0명 부담을 확인했습니다.
- 16개 seed × 관전 위주/회복·체력 로테이션의 두 전략, 최대5시즌 장기 진단에서 확정 리그6,422경기를 진행했습니다. 관전 위주16회: 귀환10/경질2/도전 중4, 회복·로테이션16회: 귀환11/경질1/도전 중4. 두 전략 모두 같은 균형 전술과 신중한 약속을 사용하며 이적·주급·전체 전술 최적화를 다룬 비교는 아닙니다. 5시즌 안에 1부 귀환하지 않은 도전은 계속 활성 상태입니다.
- 세 번째 시즌의 확정138경기 끝 면담은 직접 답변하고 네 번째 시즌으로 이동하는 기존 정상 흐름을 회귀 검사로 보강했습니다. 경기를 재생하거나 저장 복원만으로 시즌을 넘기지 않습니다.
- `615ad76` 안드로이드 APK/AAB/lint 컴파일은 성공했지만 에뮬레이터 연결이 도중 끊겨 테스트는 완료되지 않았습니다. 앱 단정 실패로 해석하지 않습니다. 다음 실행은 테스트 Gradle heap1GiB/worker1로 제한하고 [공식 에뮬레이터 문제 해결](https://developer.android.com/studio/run/emulator-troubleshooting)에 따른 Vulkan 비활성화로 재검증합니다. 호스트 메모리/커널 로그를 보관해 재발 원인을 확인합니다. 앱의 보안 설정이나 실제 사용자 기기 설정을 바꾸지 않습니다.

## 결말 이후의 이야기와 시즌 진입

경질/1부 귀환 뒤에는 ClubStory의 새 답변도 막습니다. 이전에 한 대답과 당시 도착한 이야기는 읽기 전용으로 볼 수 있습니다. 기존 영수증 검증과 저장은 유지하고, 무료 유예로 실제 활성 상태가 되면 다시 답변할 수 있습니다. 일반적인 미답변 구단주 요청은 대화 자체를 막지 않습니다. 종료 저장의 첫 제목 화면도 바로 ‘이번 삶의 결말 보기’를 표시합니다.

2시즌 이후에는 새 5부 감독직 계약서를 반복해서 보내지 않습니다. 실제 승격/잔류/강등 이야기가 새 시즌을 엽니다. 이미 저장된 2시즌 이후 취임 답변은 그대로 읽고 활성 상태에서 이어서 답할 수 있게 유지합니다.

실제 브라우저의 리그 10R은 90+4분 1:1 무승부로 끝났습니다. 기록/선수 사진, 두 팀 22명 이름, 실제 68분 득점 리플레이, 명시적 결과 확정과 11R 재접속을 확인했습니다. 실제 자연 경질(4시즌 2부, 리그168경기/92승/323점) 파일도 불러왔으며 끝난 삶 대화 8페이지를 네 크기에서 넘침 없이 확인했습니다.

전체 검사152 suites/1134 checks와 최종 구단 이야기16/기억 이야기7/환생 UI11그룹, PWA14/Android 자산11그룹을 통과했습니다. QA 로그는 저장소 밖 `work/qa-fm-rebirth-20261011/tests-ended-story-final.log`에 있습니다. 마지막 읽기 전용 안내 문구는 별도 UI 회귀 검사로 재확인했습니다.

`b041ad0`도 소스 CI/Pages/네이티브 컴파일·lint는 성공했으나 첫 에뮬레이터 테스트 중 연결을 잃었습니다. 호스트 로그에는 OOM 증거가 없었습니다. Emulator37.2.12에서 기존 `swiftshader_indirect`는 [공식 문서](https://developer.android.com/studio/run/emulator-acceleration)상 폐기된 모드여서 권장 소프트웨어 선택 모드 `-gpu software`로 재검증합니다. 원인을 단정하거나 테스트를 생략하지 않습니다.
