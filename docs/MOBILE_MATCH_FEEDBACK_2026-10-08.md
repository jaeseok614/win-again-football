# 모바일 경기 피드백 반영 — 2026-10-08

실제 APK 플레이 피드백에 따라 경기 관전, 첫 선수단 안내와 이적 검색을 개선했다.
현재 schema/engine 10 캠페인, 선수 신원, 일정, 재정, 경기 결과와 RNG는 유지한다.

## 경기 관전

- 경기장에는 얼굴 대신 작은 유니폼과 번호를 표시하고 공은 별도 전경 레이어로 그린다. 얼굴은 명단·선수 상세에서 볼 수 있다. 작은 경기장에서는 현재 동작에 관계된 선수 이름만 표시한다.
- 공격 장면은 공 회수 → 확보 → 첫 패스 → 운반/측면 돌파 → 크로스/침투 패스 → 슈팅 준비 → 슈팅 → 골키퍼 대응/차단 → 재전개의 순서로 연결한다. 윙 돌파자는 실제로 동료들보다 먼저 전진하고 성공한 돌파의 수비자는 뒤따른다.
- 골키퍼는 슈팅 방향으로 움직여 각도를 좁히고 공을 받은 뒤 선방을 알린다. 득점 문구·전경 카드·표시 점수도 공 도착 뒤에 나온다. 슛 준비 때 공과 실제 슈터 위치가 일치한다.
- 같은 시계로 장면과 결과를 동기화한다. 전술/교체 창을 열면 정지하고 닫은 뒤 직접 이어간다. 아직 표시되지 않은 결과는 정지 뒤에도 유지한다. 단순 이어가기는 5분 하이라이트로 잘못 분류하지 않는다.
- 보통 장면은 5.75초이며 느리게/빠르게 설정의 0.5×/2×가 연출에도 적용된다. 5분 진행과 동작 줄이기는 원래 결과를 즉시 보여준다. 미리보기는 항상 실제 12초 이내로 끝난다.
- 점유율(추정), 슈팅, 선발 평균 체력, 남은 교체를 항상 표시한다. 중계는 세로 화면 15px, 짧은 가로 화면 14px의 고대비 글씨다. 세로 화면의 조작은 채워진 두 줄, 짧은 가로 화면은 두 버튼 그룹을 한 줄로 놓아 경기장 공간을 확보한다.
- 2D 장면은 기록된 엔진 사건을 설명하는 연출이다. 별도 충돌 물리나 태클 통계, 추가 골·난수를 만들지 않는다.

## 전체 선수단과 검색

- 첫 안내와 감독실에서 우리 팀 18명을 한 명단으로 연다. 선발/후보, 전체·선발 평균 종합, 포지션별 인원, 실제 체력과 별도 컨디션을 비교할 수 있다. 종합은 주 포지션 능력의 가중 평균이며 엔진 보너스가 아니다.
- 이름을 누르면 상세 보고서를 열고 닫으면 명단으로 돌아간다. 안드로이드 뒤로가기는 현재 초점이 있는 자식 창부터 닫는다. 명단을 닫아야 가이드 다음 단계로 진행한다. 작은 화면의 목록만 내부에서 세로로 스크롤한다.
- 이적 필터는 빈 검색어로도 즉시 적용된다. 타이핑은 180ms 뒤 반영하고 검색어 삭제는 즉시 반영한다. 필터 변경 때 현재 입력을 읽어 지운 검색어가 다시 나타나지 않게 했다. 한국어 조합이 끝나기 전에는 입력창을 교체하지 않는다. 다른 화면으로 이동한 뒤 지연된 검색이 그 화면을 다시 그리지 않는다.
- `전체 후보 보기`는 이름·구단·포지션·능력·관심/예산 제한을 함께 해제한다. 검색만으로 영입하거나 돈을 사용하지 않는다.

## 초상화와 용량

- 손헝민은 한국인 인물 특징과 검은 머리를 가진 원본 일러스트로 교정했다. 나머지 토투넘 패러디 선수 17명도 피부색·헤어스타일을 대응 인물의 특징에 맞춰 수정했다. 실사 사진을 다운로드하지 않았다.
- 기본 7×4, 1659×948 격자와 기존 선수별 셀 인덱스를 유지한다. 손헝민은 21번 셀이다. 영입·유소년·상대 선수의 신원별 연결도 유지한다.
- 산출물: `source/dist/assets/player-faces-v16.webp` (244,128바이트). 내장 이미지 생성 도구로 기존 원본 아틀라스를 편집하고, 외형 변경 없이 WebP로 압축했다. [최종 프롬프트](PLAYER_PORTRAITS_V16_PROMPT.txt).
- 공개 게임 화면 파일은 이전 약 5.1MB에서 약 2.15MB로 줄었다. 기본 얼굴 이미지는 한 번만 공유하고 모든 이미지를 오프라인 번들에 넣는다.

## 검증 범위

전체 소스 **101 suites / 772 checks**, 공개 PWA 캐시·업데이트 **14개**, Android 자산·브리지 **11개** 검증이 통과했다. 실제 Chrome에서 320×568, 360×640, 390×844, 412×732, 640×360, 844×390, 768×1024, 1440×900의 모든 경기 단계를 확인했다. 전체 명단과 검색은 작은 세로·가로 화면에서 실제 버튼·입력 동작으로 검사했다.

실제 버튼으로 빠르게 설정의 경기를 90분까지 진행했다(약 105초). 득점 장면 도중 전술 창을 열었을 때 경기 분·연출 시간·아직 표시되지 않은 결과가 멈추며, 닫은 뒤 수동 재개하는 것을 확인했다. 종료된 경기 전체 상태가 동일한 시작 상태를 엔진으로 독립 실행한 결과와 일치했다(1–0, 슈팅 3–2). 다시 열면 시즌·라운드·RNG·점수·종료 단계가 그대로 복원된다. 페이지 오류나 경기 화면 스크롤은 없었다.

공개 번들 **2,152,178바이트**, Android 오프라인 번들 **2,153,807바이트**(SHA256 `ab3355bf765dd30ab617186728543caee55757a1439e56388356b85b30bae581`)다. 이전 공개 번들 5,095,306바이트 대비 약 58% 작다.

### 성능 측정의 범위

한 PC의 Chrome을 4배 CPU 제한, 360×640 화면으로 실행하고 이전/최신 번들을 각각 세 번 새 컨텍스트에서 열었다. DOMContentLoaded 중앙값은 이전 3,281ms, 최신 2,001ms였다. 기본 얼굴 이미지 decode 중앙값은 255ms에서 53ms로 줄었다. 샘플이 작고 파일 URL로 실행했으므로 네트워크 로딩이나 실제 Android 성능을 보장하는 수치가 아니다.

같은 제한에서 최신 경기 10초의 화면 간격 중앙값 16.7ms, 95백분위 33.3ms, 50ms 이상 작업 11건(최대 97ms)을 관찰했다. 새 연출이 모든 저사양 기기에서 60fps라고 주장하지 않는다. 실기기 성능 검증을 후속 작업에서 계속한다.

새 안드로이드 계측 테스트는 전체 선수단 안내, 상세→뒤로가기, 빈 검색어 필터, 입력/삭제를 검증한다. APK·AAB·lint·에뮬레이터 결과는 PR #24의 최신 CI에서 확인한다. 실제 물리 휴대폰의 성능 측정과 Google Play 공개 출시를 완료했다는 뜻은 아니다. 합성 저장, QA 스크린샷과 측정 스크립트는 커밋하지 않는다.
