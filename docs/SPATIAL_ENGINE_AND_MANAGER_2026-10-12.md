# 공간 전개 1단계와 첫 감독실

## 실제 변경

RoboCup SoccerServer의 고정 간격 이동, 가속·체력, 공의 속도와 접촉 원칙을 참고한 원본 JavaScript 공격 계산기입니다. C++ 서버 코드나 FM의 비공개 엔진을 이식했다고 주장하지 않습니다.

- 첫 킥오프의 상대 확인 버튼에서 `spatialSetup.version=1`을 기록합니다. 당시 상대 포메이션과 실제 우리 전술 배치를 고정합니다. 이미 시작한 v10 경기는 도중에 규칙을 바꾸지 않습니다. 저장 키·스키마·패키지 ID 유지.
- 오픈 플레이 기회에서 22명(퇴장 제외)의 공간을 최대85회, 100ms 간격으로 계산합니다. 선수별 속도·남은 체력·가속, 가까운 두 수비의 추격과 나머지의 커버를 사용합니다. 우리 능력은 실제 선수/영입 선수, 상대 능력은 현재 상대 전력 프로필입니다.
- 미드필더의 옆 공간 확보, 윙 전진, 공의 비행, 빠른 패스의 구간 접촉, 수신 후 실제 전진과 뒤따르는 태클을 연결합니다. 통과된 패스와 막힌 패스가 모두 나옵니다. 패스 순간 공/두 번째 수비/중앙선을 기준으로 오프사이드를 판단합니다.
- 슈팅 위치·주변 수비 압박으로 기존 xG를 조정합니다. 공간 결과가 실제 기회/슈팅/득점에 반영됩니다. 새 골의 도움은 실제 전달자이며 개인 돌파·중거리 마무리는 가짜 도움을 기록하지 않습니다.
- 화면과 다시 보기는 같은 고정 계산을 재사용하고 장면별 WeakMap에 캐시합니다. 매 프레임 엔진을 진행하거나 난수를 더 뽑지 않습니다. 선방은 골키퍼가 슈팅 방향으로 움직여 공을 만난 뒤 공개합니다. 양 팀 전체 이름 표시 유지.
- 분당8회 난수 계약을 유지합니다. 새 공간 영수증은 저장 복원 시 당시 선발/전술/실제 체력/난수로 재계산해 검증합니다. 없는 영수증이나 바뀐 좌표/규칙은 거부합니다. 이전 경기의 점수/xG/기록을 재작성하지 않습니다.

아직 경기 전체를 100ms마다 계속 계산하는 완전한 자율 축구 엔진은 아닙니다. 기회 발생은 기존 분 단위 모델을 사용하고 그 안의 오픈 플레이를 공간으로 결정하는 혼합 구조입니다. 세트피스는 기존 전용 로직을 유지하며 상대 개별 능력·전체 경기의 지속 소유권·골키퍼 물리 판정은 후속 범위입니다.

## 첫 화면과 원본 그림

imagegen으로 만든 가상의 한국인 감독과 작은 5부 감독실을 타이틀/필수 첫 출근 안내에 연결했습니다. 원본1536×1024 그림을 크기 변경 없이 WebP72로 인코딩해121,220바이트로 묶었습니다. 실존 얼굴/구단 로고/외부 런타임 이미지 없음. 제작 프롬프트는 한국인32세, 네이비 트레이닝복, 낡은 전술 수첩, 구단 사무실 창밖 작은 경기장, 희망적인 아침 분위기였으며 원본 생성 결과를 직접 확인했습니다.

타이틀과 첫 두 페이지에서 같은 이미지 데이터를 한 번만 포함합니다. 작은 화면의 취임/경질 안내는 의미를 유지하면서 압축했습니다. 짧은 가로 타이틀은 글/버튼 왼쪽, 감독 오른쪽입니다. 취임 면담의 실제 두 답변은 계속 필수이며 그림을 보는 것으로 시간/선수/이사회 여유를 바꾸지 않습니다.
