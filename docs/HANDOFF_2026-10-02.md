## 이 브랜치에 추가한 미완료 기능

1. `opposition.js`, `opposition-ui.js`, `opposition.css`: 경기 전 상대 보고서,
   가상 선수 11명·포메이션·전술·능력·컨디션, 우리 전술과의 비교.
   원래 상대 팀 능력 평균을 보존하도록 선수 능력을 구성했습니다.
   경기장 상대 포메이션 표시와 경기 중 체력 숫자·교체 선택도 연결했습니다.
   카드 도입 전 상대 보고서 4개, Matchday UI 13개, Movement UI 10개 검증을 통과했습니다.
   최신 통합 상태의 모바일 화면·Android 검증은 아직 안 했습니다.
2. `discipline.js`: 새 시즌 경기의 경고·두 번째 경고·퇴장 초안.
   기존 경기 RNG와 별도의 결정적 계산을 사용합니다. 명목 선발 11명은 저장 호환성을
   위해 유지하고 실제 활동 인원·체력·출전 시간·경기장에서는 퇴장 선수를 제외합니다.
   엔진/통계/중계/움직임에 연결했지만 **전체 테스트는 실패하는 상태입니다.**
   이 버전을 APK로 배포하거나 PR #1의 완료 버전으로 소개하지 마세요.
3. 구단주 갈등·투자 상담은 **아직 구현하지 않았습니다.**
   선수 팀 대화(경기 전, 45분, 65분)와 경기 전후 인터뷰는 완료 버전에 이미 있습니다.

## 먼저 해결할 문제

- `node source/run-tests.cjs`는 현재 `test-campaign-file.cjs`의 시즌 저장/복원에서 실패합니다.
- `test-season.cjs`는 출전 합계 2970을 기대하지만 퇴장으로 2876이 됩니다.
- `test-statistics.cjs`는 고정 출전 합계 990을 기대하지만 958이 됩니다.
  퇴장 전후의 실제 출전 시간을 검증하도록 모델과 테스트를 함께 정리하세요.
  단순히 검증을 삭제하거나 고정 값을 모두 느슨하게 바꾸지 마세요.
- 시즌/통계/커리어/건강/컵/유럽의 검증에 아직 990분 또는 선수 90분 가정이 있습니다.
  실제 퇴장 시간에 맞게 정산·성장·저장 복원을 수정하고 구버전 결과를 보존하세요.
- Engine.restore의 구간 결정 검증에서도 퇴장 선수 교체를 거부해야 합니다.
- 상대 보고서가 퇴장 인원과 활동 선수의 컨디션을 정확히 표시하도록 연결하세요.
- 카드별 회귀 테스트: 저장/복원, 2회 경고 퇴장, 퇴장 뒤 득점·체력·출전 중단,
  교체 불가, 위조 카드/결정 거부, 과거 저장과 RNG 유지.
- 다음 경기 출전 정지/누적 경고는 미구현입니다. 구현 범위를 명시하고 실제 규칙과
  출전 가능 선수 부족 시 처리를 함께 설계하세요.
- Android GameSmokeTest에는 상대 보고서 11명 확인을 추가했지만 아직 실행 전입니다.
- 이 브랜치의 root PWA는 이전 검증 완료 버전입니다. 소스 완성 후 전체 번들을 다시
  빌드해야 하며 source 수정만으로 공개 웹이 갱신되지 않습니다.

## 구단주 기능의 다음 구현 범위

- 리그 경기 준비 중 주 1회 구단주 면담: 투자 요청, 성적 약속, 유망주 출전 약속,
  선수 보호 의견. 실제 재정·구단주 신뢰·약속 이행에 영향을 주도록 구현하세요.
- 투자 수락 시 실제 finance ledger에 지원금을 한 번만 기록하고 저장 복원 때 검증.
- 성적/유망주 약속은 확정된 statistics 경기 기록으로 이행률을 계산하세요.
- 구버전 저장은 현재 시점부터 면담 기록을 시작하며 과거 재정·결과를 변경하지 않습니다.
- 감독실 홈에서 관계·면담·진행률을 확인하게 하고 숨긴 화면의 계산은 건너뜁니다.
- 구단주 해임 등 전체 FM 기능을 이미 구현했다고 설명하지 마세요.
