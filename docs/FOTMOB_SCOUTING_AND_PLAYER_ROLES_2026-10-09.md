# 2026-10-09 선수 얼굴·역할·영입 선택

게임의 토투넘은 가상 2024/25 선수단을 유지한다. 풋몹의 현재 소속·최근 부상·경기 평점과 게임의 능력치를 동일시하지 않는다. 이번 작업은 실제 선수의 주발·주요 위치·플레이 특징을 조사하고, 선발과 영입에 쓸 수 있는 원본 게임 평가로 표현하는 작업이다. 실제 사진을 내려받거나 다른 게임의 능력치 데이터베이스를 복제하지 않았다.

## 구현

`player-scouting.js`는 실제 현재 기본 능력 여섯 개와 신원별 특징을 읽어 기술·판단/성격·신체를 1–20으로 계산한다. 공격수는 26개, 골키퍼는 별도 선방/포구/전진/배급/공중볼 항목을 포함한 24개 항목이다. 정신 성격 여섯 값은 기존 대화 모델의 실제 값을 그대로 읽는다. 선수 유형, 활용, 주의점과 여섯 축 레이더를 표시한다. 14개 역할의 가중치와 친숙한 세부 위치를 함께 읽으며, 중앙 수비수에게 자동으로 윙백 역할을 추천하지 않는다. 훈련 후의 실제 능력으로 다시 계산한다. 모델을 읽어도 경기·RNG·자금·저장은 변하지 않는다.

역할 점수와 레이더는 0–100 코치 평가다. 실제 경기 통계·FotMob 백분위·경기 엔진 추가 보너스가 아니다. 경기 결과에는 기존 여섯 기본 능력과 검증된 전술·대화·피로 규칙이 적용된다. 기본 선수 계약, 능력 성장 기준, schema/engine 10, 이미 유효한 현재 캠페인과 신원을 바꾸지 않는다.

토투넘 18명은 새로운 원본 얼굴 아틀라스를 사용한다. 손헝민의 양발, 판더벤느의 왼발·커버, 포로우의 크로스, 매디쏜의 시야, 히샬리쏭의 헤더 등 장단점을 구분한다. 골키퍼·후보까지 얼굴이 서로 다르고 현재 신원에 고정된다. [정확한 생성 프롬프트와 출처](PLAYER_PORTRAITS_V19_PROMPT.txt)를 기록했다. 전체 공개 파일은 새 그림을 포함해 이전 기준보다 작다.

영입 후보를 8명에서 32명으로 확대했다. 새로운 24명은 게임 균형을 위한 가상 후보이며 실제 축구 선수의 시장 가치나 이적 가능 명단이 아니다. £20,000–108,000 이적료, £600–2,400 주급의 베테랑·성장형·역할 특화 선수가 있다. 주발과 세부 위치는 신원에 고정된다. 기존 8명 계약은 보존한다. 32명 모두 정상 영입·저장 복원·경기 정산 검증을 거친다.

이름을 비워도 구단·포지션·나이·주발·역할로 찾고, 세부 조건에서 역할 기준·주요 능력·성장 한계·정렬을 선택한다. 한 페이지에 8명만 렌더링한다. 변경한 필터는 첫 페이지로 돌아가며 모든 후보를 빠짐없이 보여준다. 비교는 펼침 영역으로 접고, 교환 대상을 바꿔도 펼침과 포커스를 유지한다. 최종 팝업에는 실제 비용·주급·성장 경험과 역할·세트피스 차이를 분리한다. 취소는 무변경이며 확정은 최신 구단 상태의 정확한 계약 한 건만 실행한다.

## 검증 기록

회귀 테스트에는 세부 값의 범위·모델 무변경·성격 값 일치·골키퍼 전용 평가·친숙 위치 필터·신원 유지·반환 모델 격리·모든 새 후보 계약과 복원·훈련 후 갱신·역할/주발 복합 검색·4페이지 완전 탐색·검토 취소를 포함한다. 상세 실행 결과와 공개/Android 파일 해시는 HANDOFF.md의 이번 작업 항목에 기록한다.

브라우저는 공개 빌드의 실제 UI를 조작했다. 320×568, 360×640, 390×844, 640×360, 844×390, 1365×900에서 선수 보고서의 가로 넘침이 없고 닫기 버튼은 46.5px다. 390×844에서 왼발 측면 전진 필터로 3명을 찾고, 벤 데이비쑤와 루이스 멘델을 비교했다. 교환 대상을 바꿔도 펼침이 유지됐다. 취소 전후 전체 캠페인이 같고, 확정 후 £132,000/새 신원 r_d1/계약 1건을 실제 백업으로 확인했다. 합성 검증 저장·화면은 저장소 밖 work/qa-scouting-20261009에만 보관한다. 실제 물리 휴대폰 시험이나 이번 코드의 새 APK 컴파일 결과로 간주하지 않는다.

개발 미리보기에서 오래된 같은 번호의 모듈 캐시와 퇴역 저장이 남아 있음을 확인했다. 바뀐 모듈의 URL과 전체 오프라인 목록을 갱신하고, 캐시를 제외하는 별도 QA URL에서도 최신 공개 빌드를 확인했다. 사용자의 오래된 원본 저장을 지우지 않았다. 업데이트 직후 열린 탭이 이전 완전한 파일을 잠시 유지하는 PWA 동작은 다음 개선 단계에서 점검한다.
